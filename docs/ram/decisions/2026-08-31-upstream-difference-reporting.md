# 本家AI-DLCとの差分を自発的に提示する

- 日付: 2026-08-31
- 状態: Accepted
- GitHub Issue: [#17](https://github.com/sori883/ai-dd/issues/17)
- 関連: [初期実装の境界](2026-08-29-initial-implementation-boundaries.md)、
  [Workspace読み取り接続の計画](2026-08-31-workspace-reading-composition-plan.md)

## 背景・ユーザーの指示

workspace読み取り接続の詳細計画に対し、ユーザーは実装を承認した。
あわせて「今後からでいいから本家実装と差分がある時に提示するようにしてください」
「次回から言われなくても出来るようにエージェント.mdに書いておいて」と指示した。

参照実装に合わせる部分と、Go移植・安全性・段階的実装のために異なる部分を、
ユーザーが追加で質問しなくても把握できる運用にする。

## 決定

1. プロジェクトルートの`AGENTS.md`に、本家との差分提示を継続的な必須ルールとして記載する。
2. AI-DLC由来の機能を扱う際は、参照バージョン・根拠・確認範囲を明らかにする。
   ローカルスナップショットと最新upstreamを混同しない。
3. 差分がある場合、実装前の計画と完了報告に、本家の挙動、本実装の挙動、理由、
   利用者・互換性への影響を記載する。名前・path・symlink、エラー、保存形式、API等も対象にする。
4. 意図的な非互換、段階的実装で未実装・対象外の機能、未検証・不明点を区別する。
   未確認を「差分なし」と断定しない。
5. 承認済み計画にない観測可能な差分を追加する必要が生じた場合は、実装前に提示して
   明示承認を得る。採用した差分と理由はRAMへ記録し、索引も更新する。
6. 独立レビューでも、差分の提示・必要な承認・記録に漏れがないか確認する。

## 影響・適用範囲

今後のAI-DLC関連タスクで、個別の指示を待たずに適用する。過去の完了タスクを一括再調査する
指示とは扱わない。今回の接続処理も、承認済み計画の差分を完了報告へ添える。
本家への完全追従を要求する方針変更ではなく、差分を可視化して判断・承認できるようにする運用である。

本方針は開発プロジェクトの記憶であり、成果物AI-DLCが利用先で管理するknowledgeとは分離する。

## 未解決事項

現時点で追加確認事項はない。参照スナップショットを更新した場合は、新しいバージョンを根拠に
対象機能を再比較し、以前の差分記録がそのまま有効だと推定しない。
