# 現状解析をSpace共有にし、構成図を別文書にする

状態: 配置方針はAccepted。ユーザーが現状解析をIntentごとではなくSpace共有とし、構成図を別途作るよう指定した。
[Sensor整理案](2026-09-08-sensor-catalog-proposal.md)と[以前の具体案](../../design/space-reverse-okf-sensor-plan.md)にある
現状解析を今回Intent専用成果物として扱う部分、および会話で提案したdesign/<intent_id>/current-analysis.mdを置換する。
既存資料は削除しない。この合意だけでSensorの詳細な永続形式や実装全体が確定したとは扱わない。

## 配置と役割

現状解析はSpace共有として保持する。構成図は現状解析本文とは別のOKF文書にする。
具体的な配置案はknowledge/knowledge/current-analysis.mdとknowledge/knowledge/architecture.md。
前者は現行の機能・動作・制約と根拠、後者は構成要素・役割・依存関係・データの流れを説明する。
構成図はOKF Markdownの本文内にMermaidで記述する案。未実装の将来構成と現行構成を混同しない。
要件と実装計画は引き続きIntent別、設計判断の理由はknowledge/ADR配下へ置く従来方針を維持する。

## Sensorへの影響と未確定事項

共有の現状解析を現在Intentとintent_idが一致することだけで合否判定しない。
新しいIntent開始だけを理由に本文・intent_id・生成日時を書き換えない。
現状解析と構成図について、文書の実在・OKF形式・参照元の版・今回検証する文書の版を照合し、
内容が今回の調査対象に適合するかは独立reviewが確認する案を推奨する。
現在Intentが参照した共有文書は、その参照先と対象版で結び付ける。保存の具体形式は未確定。
資材や文書が変われば影響する検証をやり直し、記述に差分があるとき共有文書を更新する。
共有文書の鮮度を今回段階の開始日時だけで判定する方式は、そのまま適用できない。
必要となる段階・適用条件、再確認の保存方法、新規開発時の扱いは実装計画で確定する。
