# Intent単位のKDR記録とhookの保証範囲

- 日付: 2026-09-07
- 状態: Accepted（以下の製品方針への直接承認。実装計画全体の承認ではない）
- 設計: [OKF・KDR・hookの最小構成案](../../design/okf-kdr-minimal-workflow.md)

## 回答と採用する方針

「強制」は通常のAI操作における記録漏れ防止を意味するかという確認に、ユーザーは
「そうです。intents単位にKDRファイルを作成し記録することを強制します」と回答した。

IntentをKDRの保存単位とし、各IntentにKDRファイルを作成して記録することを必須にする。
同じIntentの試作・実装・テスト・修正・再開では、そのKDRを継続して更新する。
hookは通常の対応するAI操作でCLIを使った作成・記録を求め、記録漏れを防ぐ。
CLI以外の書込みをOS権限で全面禁止する構成は、この「強制」の要件には含めない。
工程遷移stateや全操作auditを、この必須化のために復活させない。

## 置換対象と残る実装詳細

[最小構成の方向性](2026-09-07-okf-kdr-minimal-product-direction.md)に残していた
hookの保証範囲の確認点と、設計案の曖昧だった「小さな変更ごと」という保存単位を置換する。
過去の記録は検討履歴として保持する。

KDRの配置path、Intentとの対応方法、hookごとの機械的な確認条件、更新漏れの判定、
中断・保存失敗時の扱いは、この方針を満たす実装計画で具体化する。
この回答を既存CLI・stateの変更、移行・削除、外部tool導入、新ロードマップ全体の実装許可へ拡張しない。
