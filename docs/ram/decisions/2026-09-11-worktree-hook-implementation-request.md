この依頼は③の対応を進める許可であり、既に依頼された対応そのものへの再承認は求めない。ただし、同じGitリポジトリの複数worktreeが使う管理元を一つに固定するか、複数の管理元を明示登録して振り分けるかは、従来の「1調整root内の横断管理」では決まっていない。起動場所・保存先・他の会話への影響が変わるため、自己完結した計画へ選択肢と影響を整理する。

維持する境界は、Goの単一binaryと標準ライブラリ、メインAIによるnative agent起動、既存assignmentによる別worktreeの並列worker、明示的な停止確認と割当解放、通常のCodex hook信頼確認である。全書込み先の監視、本人・全process終了の認証、時間経過での予約解放、全操作auditは追加しない。Codexの更新や、ユーザーが利用中の主checkoutへのhook配置はこの記録だけでは実施しない。

固定Codex 0.153.4で確認したhook探索とcwdの意味を用いる。最新Codexとの同一性は主張しない。複数rootの自動推測で保存先を選ばず、未確定の重要な運用選択を決定済みとして実装しない。

[具体計画](../../design/shared-worktree-hooks-plan.md)は、明示した一つの管理元から親会話を始める共有modeを推奨する。計画担当の独立した読み取り点検で、主checkoutと管理元が同じ場合の既知hook変換、現行binaryを用いた実装前の実機gate、管理先移転時の旧entry撤去と新規登録手順を補足した。コード・設定・Issue・PRは変更せず、テストと実機もまだ行っていない。管理元を一つに固定する利用条件への回答と、具体計画の実施範囲を後続記録へ残す。
