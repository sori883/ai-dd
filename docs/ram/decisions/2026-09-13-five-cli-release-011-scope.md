# 五つのCLIへの分離を0.1.1に含める

2026-09-13。ユーザーは、`aidlc-install`、`aidlc`、`okf`、
`natural-japanese-go`、`aidlc-dist`へ分ける説明に対し、
「はい、この変更も0.1.1に入れ込みたいです」と回答した。
五つのCLIへの分離を0.1.1の実装・配布範囲に含める直接指定として扱う。

[五つのCLIの構成](2026-09-13-five-cli-product-layout.md)を引き継ぐ。
[インストーラー分離の記録](2026-09-13-separate-installer-and-runtime.md)にある
公開準備の中断は、旧一体型構成をそのまま公開しないためのものだった。
今後は分離後の構成を対象に準備を進める。旧33 Stageロードマップは実装許可に用いない。

利用者が導入するときは`aidlc-install`を使う。日常の処理を担うのは
`aidlc`、`okf`、`natural-japanese-go`であり、`aidlc-dist`は開発者の梱包用である。
`okf`は現行のGo実装から公開コマンドを切り出す。
本体内部のセンサー等が使うOKF処理は共通Go packageを再利用できるため、
処理の複製や、内部の読取りごとに別プロセスを起動する設計は要求しない。
各CLIはGoの一つの実行ファイルとして提供する。

分離ではCLIの入口に加えて、hookが識別する実行ファイル、skill・agent・工程手順が参照する
コマンド、配布資材、版の照合、ライセンス表示、検証と導入案内を揃える。
Codexへの新規配置を対象とし、Claude・Copilotの再開、旧配置の互換・移行、
新しい外部Go moduleの導入は含めない。共通手順の原稿は引き続き一箇所で管理する。

この回答だけでは一意に決められない次の点は、具体案と影響を提示して確認する。

- 引数で指定した版のCLI・資材を取得する方式か、インストーラー自身と同じ版だけを導入する方式か。
- 3つの日常用CLIをプロジェクト内の`aidlc/bin/v0.1.1/`へ置くか、ユーザー共通の場所へ置くか。
- 独自部分をMIT・著作権者`2026 sori883`として公開してよいか。外部由来の表示は別途保持する。

上記はユーザーへ確認中であり、回答を推定して実装しない。
一般的な「分離を0.1.1に入れてよいか」という許可は得られているため、同じ許可は再要求しない。
実装前に、回答を反映した自己完結した計画を整える。

[具体計画](../../design/five-cli-release-011-plan.md)に、確認中の両案、CLIの入口、hookの識別、
版付き資材の取得・配置、変更ファイル、単独writer、順序付きTDD、独立review・final・公開の順序を記載した。
計画は3点の回答待ちであり、確定済みの実装契約として扱わない。
