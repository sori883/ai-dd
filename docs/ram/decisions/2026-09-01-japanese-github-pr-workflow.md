# GitHub Issue・PRを日本語の実装記録として運用する

- 日付: 2026-09-01
- 状態: Accepted
- GitHub Issue: [#27](https://github.com/sori883/ai-dd/issues/27)

## 背景・承認

ユーザーは、現在何が実装されているかをPRで確認すること、今後のPRも実装範囲を
確認できる内容にすること、Issue作成・PR作成・PR参照を扱うskillを作成すること、
GitHub上の対応を基本的に日本語にすることを求めた。

親エージェントは、`github-pr-workflow` skill、日本語のIssue・PRテンプレート、
`AGENTS.md`とエージェント運用文書への永続ルール、RAM記録を含む計画を提示した。
ユーザーは2026-09-01に「はい、OKです。お願いします」と明示承認した。
実装開始後、ユーザーは、通常の「これは作らない」という対象外項目はIssue・PRへ記載せず、
特殊な条件がある場合だけ記載するよう追加で明確化した。

## 決定

1. 現在の実装状況は、default branchへマージ済みのPRを第一の履歴根拠として確認する。
2. Draft、Open、未マージのClosed PR、ローカル変更だけを実装済みとは扱わない。
3. マージ済みPRは導入時点の証拠であり、現在状態を答えるときは後続PR、revert、現在の
   コード・テストを必要な範囲で照合する。
4. Issue・PRのタイトル、本文、コメント、レビュー要約、ユーザーへの報告は、コード識別子、
   コマンド、パス、状態名、既存タイトルの原文を除き、日本語を基本とする。
5. 新しいPRには、対応Issue、実装した機能、検証、レビューを残す。通常の未実装機能や
   「今回は作らないもの」は列挙せず、安全性、互換性、移行、利用条件に影響する特殊な制約が
   ある場合だけ特記事項として記載する。本家AI-DLCとの差分は、意図的な仕様・挙動の変更だけを
   記載する。
6. Issue・PRの作成・更新・参照では `github-pr-workflow` skillを使用する。
7. 自動マージを設定せず、mergeはユーザーの明示依頼に限定する。

## 実装と適用範囲

- skillはIssue作成、PR作成・更新、PR参照の3つの文書へ段階的に振り分ける。
- `.github/ISSUE_TEMPLATE/implementation.md` と `.github/pull_request_template.md` により、
  skill以外から作成する場合も同じ情報を残しやすくする。
- 過去のIssue・PRを一括で翻訳・改名しない。既存の英語タイトルは参照時に原文を保ち、
  意味と結論を日本語で説明する。
- PRだけを唯一の真実とはせず、現在のdefault branchと矛盾した場合は矛盾と確認範囲を示す。

## 影響・未解決事項

この決定は開発プロジェクトのGitHub運用であり、AI-DLC製品本体の仕様差分ではない。
Goコード、外部module、自動マージ設定は変更しない。

GitHub CLIや認証が利用できない環境では作成操作を完了できない。その場合は重複作成を避け、
確認できた範囲とblockerを日本語で報告する。
