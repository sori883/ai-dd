# Intentごとに承認したステージ実行計画で進める

状態: Accepted。設計案提示後のユーザー回答「hai」により、6段階・Intent実行計画・承認・Sensorの一体変更を直接承認。以前一度撤回された案ではなく、今回の新たな明示依頼を記録する。

## ユーザー指定

- Space等の初期化と目的整理・深掘りを必須とし、この順に実行する。
- 現状の構成分析は目的整理から独立したステージにする。
- 構成分析、実装計画、TDD、統合検証の実行有無・実行順は目的整理と深掘りで決め、ユーザー承認を得る。
- 決めた内容はIntentごとのファイルで管理する。stateに含めても別ファイルでもよい。
- 途中の判断で追加実行が必要なら実行計画に追加する。
- 追加・省略・並べ替えの変更ごとに承認を待つか質問したところ、ユーザーは「計画の変更ごとに承認を待つ（推奨）」を選択した。

固定advance順の[Stage Graph契約](2026-09-09-stage-graph-implementation-approved.md)と、discoveryで構成分析を必須とした部分を置換する要求である。既存記録は履歴として保持する。
各ステージのSensor・独立レビューと、以前依頼された人間承認は廃止しない。
Knowledgeのcodekb/、adr/、log/の配置と責務も維持する。

## 今回の提案と実装境界

Intentのstate.jsonへ実行計画・計画版・承認対象・実行回ごとの進捗を一体保存する。
同じステージを繰り返せるよう、ステージ名とは別の実行回IDを設ける。全操作auditや本文作業日誌は追加しない。
詳細は[実行計画方式の設計案](../../design/intent-execution-plan-proposal.md)へ記載する。

現行mainは29f4344（PR152まで）。人間承認Issue146はOpenで未merge、元checkoutで中断している。今回そのコードを変更・統合していない。
新しい永続形式・承認対象・CLI・Sensorを含む具体案への承認後に、Issue計画を更新または新設して実装する。コード・設定・Issue・PRはこの設計検討では変更しない。

## 実装開始の承認

ユーザーは具体的な設計案と実装範囲の確認に「hai」と回答した。今回のカタログ、実行回、state内計画、変更ごとの会話承認、finish、選択制Sensorと履歴への変更を直接承認として扱う。旧人間承認コードは参考にできるが未修正のまま取り込まない。

## 承認範囲の実装詳細化

[実装計画](../../design/intent-execution-plan-implementation.md)へ具体化した。state schema5、カタログschema2、CLI採番の実行回ID、承認済み計画と変更案を同じstateへ分離保存する。bootstrapの必須2回は架空の人間承認を置かず実行し、discovery終了までに選択計画を承認する。Unit結果も実行回へ対応させる。これは承認済み設計の「過去の合格を流用しない」境界を具体化したもの。

Issue146のコードは元checkoutを変更せず参照する。会話再送、JSON保存容量、履歴値検査、保存途中の再試行を回帰検証する。実装担当は1名、独立レビューと最終検証は親が管理する。

実装Issueは[#153](https://github.com/sori883/ai-dd/issues/153)。#146の人間承認も新しい実行回の契約へ統合して検証する。
