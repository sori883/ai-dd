# AI環境ごとの対応困難な機能を無理に補わない

2026-09-12。Accepted（対応範囲についてのユーザー方針）。

ユーザーは、CopilotやClaude・VS Codeへの対応について「対応できない場合は、まあ基本的に無視でいい」と述べた。全環境で同じ機能を実現するために、無理な専用機構を追加することを必須にしない。

当面はCodexとClaude Codeを優先し、VS Code版Copilotの難しい接続は保留する。VS Code自体が利用できないという判断ではない。これまでの確認は、このAI-DLCとの製品接続が未完成で、VS Codeの画面操作権限を得られず実機確認できていない、という範囲である。未検証を技術的に不可能だと断定しない。

[3環境対応の実装依頼](2026-09-12-three-host-product-implementation-approved.md)と[計画](../../design/three-host-distribution-plan.md)に対する進め方の補足とする。共通配布基盤D1は維持する。Copilot用の子による割当登録と、同居時のVS CodeによるClaude hook読込み停止は、先の質問へ個別に承認されたとは扱わず、当面実装しない。この2つの回答待ちをCodex・Claude側の独立した作業の停止理由にしない。

対応できない機能は未対応と明記する。動いていないhookを動作済みとしたり、Claudeの自動通知を人間の承認として記録したりする意味ではない。既存ファイル削除、利用者設定の無効化、既存Codexの機能削除は指示されていない。
