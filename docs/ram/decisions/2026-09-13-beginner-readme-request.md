# READMEを初心者向けの利用マニュアルにする

2026-09-13、ユーザーは、会話の経緯を知らず内部の詳細にも関心がない初心者へ向け、READMEに概要と使い方を簡潔な日本語でまとめるよう依頼した。既存READMEの技術的な紹介を、利用者の行動順に沿った案内へ整理する。

## 計画と許可

[Issue #192](https://github.com/sori883/ai-dd/issues/192)。今回の直接依頼を文書編集の許可として、mainの`15bcf7a42dc126e71cc82dd4d39a53de595cff1f`を基準に、親エージェント一人が[README](../../../README.md)、本記録、RAM索引の3ファイルだけを変更する。ユーザー指定により利用マニュアルの入口をルートREADMEに置き、詳細な説明は既存の`src/docs/user-guide.md`や`docs/distribution.md`へつなぐ。

順序は現行手順・公開状況の読み取り確認、執筆、独立したread-only review、差分安定後の親によるread-only final、PR/checks/mergeとする。reviewでは初めて使う人の導線、現行操作との一致、公開前の境界を確認する。finalはリンク、掲載コマンドと現行helpの一致、3ファイルの変更範囲、`git diff --check`を対象にする。文書だけのためGoの新しいテストやローカル全体testを実行せず、対象PRの既存CIを確認する。取り消しは文書差分のrevertで可能。

## 編集方針

- ユーザーは目的・質問への回答・計画と成果の確認を担い、AIは操作と記録を担うことを先に説明する。
- 準備、プロジェクトへの配置、Codexでの初回依頼を一続きで示す。macOS/LinuxとWindows PowerShellのパス置換例を載せ、配置後も実行ファイルを使う点を短く伝える。
- 日常操作は進捗確認、中断、再開、知識の確認、共通ルールの記録を依頼する会話例にする。IDや内部JSONの手入力を初心者の標準手順にしない。
- 計画と工程の成果を承認する流れ、変更案も承認する点を保つ。Sensor・SHA・担当予約などの内部用語は入口から省き、必要なIntentとSpaceだけを短く説明する。
- 記録の場所とhelp、詳細利用者ガイド、任意GitHub連携、開発者向けの参考元・ライセンス一覧へ案内する。
