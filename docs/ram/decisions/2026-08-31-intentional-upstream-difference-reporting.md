# 本家との差分提示を意図的な仕様・挙動の変更に限定する

- 日付: 2026-08-31
- 状態: Accepted
- 置換対象: [本家AI-DLCとの差分を自発的に提示する](2026-08-31-upstream-difference-reporting.md)

## 背景・ユーザーの指示

前の方針では、本家との観測可能な差分を広く提示するルールを`AGENTS.md`に記載した。
ユーザーはこれを絞り込み、意図的に本家の実装とずらした部分だけを対象にし、
通常の実装過程で生じる差分については都度提示する必要がないと明示した。

判断が必要な設計上の変更を共有しつつ、通常の実装差分の報告を増やさないための変更である。

## 決定

1. 自発的な差分提示の対象は、本家と異なる仕様・挙動を設計判断として意図的に採用する場合に限定する。
   対象となる場合は、実装前の計画と完了報告で、本家の挙動、採用する挙動、理由、
   利用者・互換性への影響を示す。
2. Goへの移植や通常の実装過程で結果として生じる差分（言語・型・内部構造など）や、
   段階的実装の未実装部分は、この提示ルールの対象外とする。
   差分があることだけを理由に、都度の列挙や追加承認を求めない。
3. 意図的な差分を提示する際は、参照バージョン、根拠、確認範囲を示す。
   ローカルスナップショットと最新upstreamを混同せず、未確認を「差分なし」と断定しない。
4. 承認済み計画にない意図的な仕様・挙動の変更を採用する場合は、実装前に明示承認を得る。
   合意内容と理由をRAMに記録し、索引を更新する。
5. レビュー上の差分提示・承認・記録の確認も、同じく意図的な変更に限定する。
   実装計画の承認、テスト、バグ・契約違反の確認など、他の開発ルールは変更しない。

## 影響・適用範囲

`AGENTS.md`の差分提示ルールと対応するレビュー規則を更新する。
本家と違う制約やエラー方針を意図して採用する場合は引き続き対象だが、
Goの内部構造や資源管理の表現が違うだけのケースを網羅的に報告する運用にはしない。

この決定は差分提示の運用だけを置換する。既に承認されたworkspace接続の実装契約を変更せず、
過去の計画・調査・決定記録も削除または書き換えない。

## 根拠・未解決事項

根拠は、このタスクでのユーザーによる対象範囲の訂正と、訂正内容を`AGENTS.md`へ反映する指示である。
現時点で追加確認事項はない。
