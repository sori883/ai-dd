# プロジェクトRAMの記録運用

- 日付: 2026-08-29
- 状態: Accepted

## 背景

開発中にユーザーへ確認した方針や、その回答から確定した制約を後続タスクでも再利用する必要がある。
一方、AI-DLC本体にも利用プロジェクトの知識を扱う機能があるため、開発プロジェクトの記憶と
AI-DLCが管理する成果物の知識を分離する必要がある。

## 決定

1. 本リポジトリを開発する側の永続的な記憶は`docs/ram/`に保存する。
2. 今後の設計、実装、配布、運用に影響するユーザーの回答や方針変更は、原則として回答を得たタスク内で記録する。
3. エージェントは計画、設計、調査、実装の開始前と、ユーザーへ既出事項を質問する前にRAMを確認する。
4. 記録を追加または更新した場合は`docs/ram/README.md`の索引も更新する。
5. 変更された決定の履歴は消さず、新しい記録から置換対象を参照する。
6. この運用を常に適用できるよう、必須事項をリポジトリルートの`AGENTS.md`に記載する。

## 記録対象

- 承認済みの設計・実装・配布・運用方針
- 採用または却下した選択肢と、その判断理由
- 後続作業が依存する前提や制約
- 再利用できる調査結果と根拠
- 後続タスクで解決すべき未解決事項

一時的な進捗、秘密情報、利用プロジェクト固有のAI-DLC knowledgeは記録しない。

## 影響

- 後続のエージェントは`AGENTS.md`からRAM運用を認識できる。
- 過去の判断を参照して、同じ質問や矛盾する実装を避けられる。
- AI-DLCが成果物として管理するknowledgeとは保存場所と用途が明確に分離される。

## 未解決事項

- 記録数が増えた場合のアーカイブ単位と索引の分割基準は、必要になった時点で決める。

## 根拠

- 2026-08-29のユーザー指示: ユーザーの意思決定をRAMへ蓄積し、その運用をプロジェクト用`AGENTS.md`へ記載する。
