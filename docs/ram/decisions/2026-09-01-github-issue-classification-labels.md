# GitHub Issueを主要な成果で分類する

- 日付: 2026-09-01
- 状態: Accepted
- 関連Issue: [#27](https://github.com/sori883/ai-dd/issues/27)
- 関連PR: [#28](https://github.com/sori883/ai-dd/pull/28)

## 背景・承認

ユーザーは、IssueがAI-DLC本体の機能開発か、それ以外のユーザーリクエストかを
ラベルで区別し、今回のskill作成依頼と今後作成するIssueへ適用するよう求めた。
さらに既存Issueへのバックフィルも依頼した。

親エージェントは、2つの分類ラベル、主要な成果による判断、補助ラベルとの併用、
曖昧な場合の確認、`github-pr-workflow` skillと永続ルールの更新を提示した。
ユーザーは2026-09-01に「はい、じゃ本番のやつも実装してもらっていいですか」と明示承認した。

## 決定

| ラベル | 色 | 説明 |
| --- | --- | --- |
| `機能開発` | `1D76DB` | AI-DLC本体の機能・挙動を開発または修正するIssue |
| `ユーザーリクエスト` | `D4C5F9` | ユーザー依頼によるskill・agent・文書・運用・設定のIssue |

1. 全Issueに2つの分類ラベルのどちらか1つを付ける。
2. 変更ファイルの種類ではなく、Issueの主要な成果で分類する。
3. 製品機能に付随するテスト・文書更新は `機能開発`、skillや開発運用に付随する文書更新は
   `ユーザーリクエスト` とする。
4. 2つの分類ラベルを同時に付けない。両方に見える場合はIssueを分けるかユーザーへ確認する。
5. `bug`、`documentation`等の補助ラベルは、根拠がある場合に分類ラベルと併用できる。
6. Issue作成後は、選択した分類ラベルだけが付いていることを読み直して確認する。
7. 分類ラベルがrepositoryから不在になった場合は、`enhancement`等で代用せず、
   この決定が置換されていないか確認して報告する。

## 影響

`github-pr-workflow` skill、`AGENTS.md`、`docs/agent-workflow.md`へ分類規則を反映する。
MarkdownのIssue templateでは作成時に動的なラベル選択ができないため、分類はIssue作成操作で行う。
これは開発プロジェクトのGitHub運用であり、AI-DLC製品本体の仕様・挙動を変更しない。
