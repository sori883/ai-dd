# Stage Graphと段階別手順の実装依頼

- 日付: 2026-09-09
- 状態: 実装への直接承認。定義変更時の復旧・既設更新の扱いも承認済み。

## 合意

ユーザーは「アウトプットなければないでも全然問題ない」「内容については問題ないので実装して」と回答した。
[段階別手順の提案](../../design/stage-graph-procedure-proposal.md)を実装する。
JSONに段階名・参照手順・前進と差戻しの経路を定義し、段階別Markdownに担当agent、前提文書、成果文書、手順を記述する。
4段階と開始・終了Sensor、独立レビュー合格後の前進は維持する。

outputsは文書だけとし、空配列も正当な値にする。一覧を埋めるための文書は作らない。
プログラム・テストソースをoutputsへ列挙せず、既存のコード・テスト結果の検査を継続する。
差戻し理由はIntent配下のwork-log.mdへ記録し、ADRはアーキテクチャ設計の理由に限定する。
作業記録の追加は差戻しについてであり、全操作auditや全作業の日誌を要求しない。

## 許可の範囲

今回の直接承認を根拠とし、旧33段階ロードマップの包括承認は流用しない。
Goシングルバイナリを維持し、外部Go moduleは追加しない。
具体的なファイル・保存失敗・検証条件を実装計画にまとめ、IssueとPRを通じて実装する。
進行中Intentの定義変更時の復旧と既設配布更新は提案時点で未確定だったため、重大な運用選択として追加確認している。
