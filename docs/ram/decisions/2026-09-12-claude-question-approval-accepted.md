# Claudeの承認を標準の質問画面で受け付ける

2026-09-12。Accepted（ユーザーによる承認方式の採用）。

ユーザーは、本家を調べた[改訂計画](../../design/claude-code-connection-plan.md)について、「この選択式の承認方式を採用してよいですか」という確認に「はい、良いと思う」と回答した。[前回調査](../research/2026-09-12-upstream-claude-approval-and-revised-plan.md)に残した、この方式の採用待ちを置き換える。

メインAIは対象と成果を日本語で説明し、Claude標準のAskUserQuestionでApprove（承認）／Request Changes（修正依頼）を提示する。利用者は選択して回答し、AIがCLIへ判断を記録する。専用コマンドや承認IDの転記は求めない。

## 本家との差分、理由と利用条件

本家固定AI-DLC 2.6.123は、Claudeの質問画面に加え、通常UserPromptSubmitと質問のPostToolUseの両方から入力記録を作る。確認した本家の入力記録には、自動通知の発信元を構造的に除外する検査がない。

採用するGo製品のClaude接続では、提示した承認対象に結び付いた質問のPostToolUse回答だけを承認の根拠にする。通常のSubmit、自動通知、AIによる要約を承認証拠にしない。これにより、利用者が普通のチャットで「はい」と書くだけでは承認は完了せず、質問画面の選択が必要になる。この差分と利用条件を提示した上で採用された。

承認ID・対象版・会話・質問の呼出しIDと回答を照合し、選択値とCLIのdecisionの反転、別対象への流用を拒否する。自由記述、取消、無回答、timeoutは承認待ちを維持する。計画と成果は個別に質問する。Codexの会話承認、Go単一バイナリ、既存のSensor・review・担当管理を維持し、全操作auditや本人認証を追加しない。

## 続けて実施すること

固定Claude Code 2.1.238で、通常の対話による選択・自由記述・取消とhook JSONの対応を専用試験環境で確認する。試験AIが架空の問いへ回答する操作は、実案件の成果承認とは区別する。質問の表示・応答を自動回答hookで置き換えず、通常trustと権限を用いる。観測した形式に基づきD2の入力・保存契約を具体化する。

承認方式は再確認しない。初回導入範囲（新規配置、停止後の切替、同じprojectでの併用）の未回答と、固定実機での未検証条件は別に残る。今回の回答を、未提示の移行・上書き・同時利用の選択の根拠にはしない。
