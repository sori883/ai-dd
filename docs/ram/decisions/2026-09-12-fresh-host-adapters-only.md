# 未リリースのため新規配置に限定し、AI環境への対応はアダプターに置く

2026-09-12。Accepted（ユーザーによる対象範囲と実装境界の指定）。

ユーザーは初回導入範囲の確認に対し、「既存プロジェクトなどは完全に無視でいいです。まだリリースしていないので」と回答した。続けて「coreの実装ではなく、アダプターとして、codex/claude codeに配布するもの」と指定した。

## 新規配置の範囲

一つの新規配置先でCodexまたはClaude Codeを選び、AI-DLCのskill・agent・hook・共通資材を配布する。既存AI-DLC配置の移行、更新、環境切替、同じprojectでの両環境併用、旧runtime保存の互換読込みは今回の要件にしない。承認済みの製品対応をこの範囲へ絞る。

「新規配置」はアプリケーションのコードが存在しないことを意味しない。既存ソースがあるフォルダでもAI-DLCの配置先fileが未作成なら初回配置できる。アプリ資材、利用者の設定、過去の試験成果を削除または上書きする指示ではない。既存の配置先fileが競合すれば、従来どおり書込み前に拒否する。

これにより[接続計画](../../design/claude-code-connection-plan.md)にあった導入範囲の未回答を解決する。過去の「互換不要」の回答から推測した許可ではなく、今回の未リリース製品に対する明示指定である。

## アダプターの責任

CodexやClaude固有のhook JSON、tool名、子ID、質問画面、skill・agentの書式、配置先設定を環境別アダプターが扱う。配置は既存 `src/harness/codex/` と新規 `src/harness/claude/` を入口とし、インストーラーがそれぞれを選択する。

共通の工程・Sensor・承認対象・OKF・worker占有の判定を環境ごとに作り直さない。共通側へClaudeのイベント名や環境判定を追加する前案は変更する。接続に必要な共通処理の拡張は、環境名を持たない入力・出力やinterfaceへ限定し、環境固有の受信形式と保存を共通のドメインへ持ち込まない。入口からアダプターへ接続し、アダプターが共通の判定を利用する依存関係を計画と検証で確認する。

Go単一バイナリと外部Go module追加なしを維持する。アダプターはGoコードと環境別の配布資材で構成し、別のTypeScript/Python実行環境を要求しない。CLIはagentを起動せず、メインAIが環境標準の起動toolを使用する。

Claudeの質問画面への回答だけを承認に使う[採用済みの方式](2026-09-12-claude-question-approval-accepted.md)、通常操作での記録漏れ防止という強制の範囲、同じ管理rootのworker占有、既存の工程・Knowledge・ADRの責任は維持する。Copilotは引き続き対象外。

アダプターと共通処理の正確な接続API、保存schema、固定実機で不足する確認はコード変更前の計画で具体化する。今回の範囲確定を、未確認のnative子対応やhookの拒否を成功扱いする根拠にはしない。
