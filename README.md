# AI-DD

AIと対話しながら、ソフトウェアの開発を進めるための道具です。
やりたいことを伝えると、AIが目的を整理し、調査・計画・実装・テストを進めます。進捗や設計の理由もプロジェクト内に保存するので、後から続きを再開できます。

ユーザーが行うのは、**目的を伝えること、質問に答えること、計画と成果を確認すること**です。日々の操作や記録はAIが担当します。

## 使い始める

### 1. 必要なものを用意する

- **Codex**：AIと対話する環境。あらかじめ利用できる状態にします。
- **プロジェクトフォルダ**：開発するアプリや資料を置く場所。新しく作る場合は空のフォルダで構いません。
- **標準の取得ツール**：macOS・Linuxはsh、curl、tarとSHA-256の検査ツール、WindowsはPowerShell 5.1または7とcurl.exeを使います。Goの導入は不要です。

### 2. プロジェクトに設定する

以下は**公開前のv0.1.2候補の手順**です。v0.1.2のtagとReleaseが公開されるまでは実行できません。
公開済みv0.1.1を使う場合は、その[Releaseの説明](https://github.com/sori883/ai-dd/releases/tag/v0.1.1)を参照してください。

導入先の既存プロジェクトフォルダで実行します。OSと実行中のCPUを自動で判定し、対応する一式を取得します。
取得完了とSHA-256の一致を確認してからinstallerを起動します。

macOS・Linuxの場合：

```sh
(
  set -e
  script="$(mktemp)"
  trap 'rm -f "$script"' EXIT
  curl --disable --proto '=https' --proto-redir '=https' --location --fail \
    --connect-timeout 30 --max-time 120 --max-filesize 1048576 \
    --output "$script" https://raw.githubusercontent.com/sori883/ai-dd/v0.1.2/src/bootstrap/install.sh
  sh "$script" v0.1.2 "$PWD"
)
```

WindowsのPowerShellの場合：

```powershell
$script = (Invoke-WebRequest -UseBasicParsing -Uri 'https://raw.githubusercontent.com/sori883/ai-dd/v0.1.2/src/bootstrap/install.ps1').Content
& ([scriptblock]::Create($script)) 'v0.1.2' (Get-Location).Path
$LASTEXITCODE
```

PowerShellでは処理後に元の画面へ戻ります。最後の値が0なら成功、0以外なら表示されたエラーを確認してください。

AI用の手順や設定と、日常用の`aidlc`・`okf`・`natural-japanese-go`が`aidlc/bin/v0.1.2/`へ配置されます。
設定は各役割の絶対pathを参照します。取得済み一式をinstallerへ渡すので、同じファイルを再取得しません。
必要な標準ツールがなければ理由を表示して停止します。

手動取得・オフライン導入や配置が重なる場合は、[配布・配置の手順](docs/distribution.md)を参照してください。

### 3. Codexで最初の作業を依頼する

設定したプロジェクトをCodexで開き、新しい会話を始めます。操作を確認する仕組み（hook）の信頼確認では、実行ファイルと対象フォルダを確認して許可してください。

最初は、次のように依頼します。

```text
aidlcスキルを使って進めてください。
メモを追加して一覧で見られるアプリを作りたいです。
目的を整理して、必要な作業を提案してください。
```

既存のアプリを改善する場合は、対象のフォルダと「どこを、どう変えたいか」を伝えます。AIから初期設定や作業内容について確認されたら、内容を読んで回答してください。

## 作業はどう進むか

1. **準備する**：AIが作業場所や共通ルールを確認します。
2. **目的を整理する**：質問に答えながら、作るもの・対象範囲・完成の条件を決めます。
3. **計画を確認する**：AIが必要な工程と順序を提案します。内容を確認して承認します。
4. **作業と確認を繰り返す**：AIが作業し、自動検査と別のAIによるレビューを行います。ユーザーが成果を確認して承認すると、その工程が完了します。

構成の調査、実装計画、テストを先に書く開発、全体の動作確認は、目的に応じて選びます。途中で計画を変える場合も、変更内容を確認してから進めます。

承認するときは、たとえば「この計画を承認します」「この成果で問題ありません」と答えます。直したい点があれば、そのまま伝えてください。分からないまま承認する必要はありません。

## よく使う依頼

一つの目的を持つ作業を**Intent（インテント）**と呼びます。AIがIDを付けて管理します。同じ作業の修正や再開では、同じIntentを使います。

| やりたいこと | AIへの伝え方の例 |
| --- | --- |
| 進捗を知る | 「今の進捗と、次に私が確認することを教えてください」 |
| いったん止める | 「ここで中断して、続きから再開できるようにしてください」 |
| 続きから再開する | 「前回のメモアプリ開発の続きを再開してください。候補が複数あれば確認してください」 |
| 仕様や判断を調べる | 「メモの保存方法と、その方式を選んだ理由を教えてください」 |
| 共通ルールを残す | 「このプロジェクトではエラー表示を日本語にするルールを記録してください」 |

別の会話からも再開できます。IntentのIDが分かれば一緒に伝えると確実です。別の目的を始める場合は「新しい作業として始めたい」と伝えてください。

## 記録はどこに残るか

通常、記録はプロジェクト内の`aidlc/spaces/default/`に保存されます。`default`は、作業と知識をまとめる場所であるSpaceの初期名です。

| 保存先 | 内容 |
| --- | --- |
| `knowledge/` | 要件、計画、現在の仕様、設計判断の理由、共通ルール |
| `intents/` | Intentごとの進捗と変更履歴 |

AIに「記録を確認して」と頼めます。文書はMarkdownなので、エディターで読むこともできます。

## 困ったとき・もう少し詳しく知りたいとき

まずは、表示されたエラーをAIに伝えて「原因と再開方法を確認してください」と依頼します。記録を消して最初からやり直す前に、現在の状態を確認してください。

コマンドを自分で調べる場合は、プロジェクトに配置された役割別runtimeの`--help`を使います。版directoryは導入時に選んだRelease名に合わせます。Windowsでは各実行ファイルに`.exe`が付きます。導入用の`aidlc-install`と日常操作用runtimeは別のファイルです。

```sh
"/path/to/project/aidlc/bin/VERSION/aidlc" --help
"/path/to/project/aidlc/bin/VERSION/aidlc" intent list --help
"/path/to/project/aidlc/bin/VERSION/okf" search --help
```
