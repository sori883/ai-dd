# 文章の設計と推敲

最初に読者と読後の行動を決め、主メッセージを一文にする。主張を支える資料がない場合は、言い換えを始める前に事実・具体例・数値を調べる。推測と確認済みの事実を区別し、出典が支える範囲だけを書く。

見出しだけで論旨が通る骨組みを作る。大事な判断は厚く、つなぎの説明は短くし、どの節も同じ長さへ揃えない。仕事の文書では、議事録は決定・担当・期限・保留、調査報告は問い・方法・根拠・解釈・判断への影響、ガイドは前提・操作・期待結果・失敗時の戻り方を明確にする。メモは論点・選択肢・根拠・未決定事項、スライドは一枚の主張とそれを支える証拠を揃える。

本文は、抽象語だけで済ませず対象と動作を具体的にする。「処理の最適化を実現する」なら、何の処理がどう変わるかを書く。主語と述語、修飾語と修飾先を近づけ、一文で複数の判断を詰め込みすぎない。表記・文体・同じ概念の呼び名を統一し、専門用語は初出時に役割を説明する。引用、固有名詞、意図した反復や対比は文脈で残す。

lintは文体の疑いを返す補助であり、正誤や著者を判定しない。low_specificityは言い換えだけで解決せず、情報が足りるかを確かめる。統計検査のために体言止めや不自然な長短を作らない。自動しきい値は固定lint.pyを正本にしており、旧手動指針の「3回で型を壊す」などを自動規則にしない。

最後に見出しと各段落の先頭だけを続けて読む。結論へのつながり、根拠の不足、同じ説明の反復、急な論点変更を確認する。その後に全文で主語述語、読点、用語、出典を確かめる。依頼された書き換え範囲内で、変更理由・残した指摘・未確認の事実を返す。
