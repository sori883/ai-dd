# 二つの観点を保つ

最初にbase/headまたは対象差分が解決でき、差分があるか確認する。受け取った要求・計画の版と、現在の規約を固定する。要求の根拠がなければ推測せず、不足をメインAIへ返す。

要求観点では欠落、誤動作、依頼にない追加を確認する。規約観点では文書化された規則を引用する。次はheuristicであり、repositoryの明示規約に優先しない。

| 疑い | 確認と改善方向 |
| --- | --- |
| 意味不明な名前 | 正直な名前を付けられる責務かを確認する |
| 重複 | 同じ意味の処理なら共通化する |
| 他部品のdataへの過度な依存 | dataの所有者へ処理を寄せる |
| 同じ引数群の反復 | 一つの概念としてまとめられるか確認する |
| primitiveで重要概念を表す | domain型が不正状態を防ぐか検討する |
| 同じ分岐の反復 | 一箇所へ責務を集める |
| 一変更が多数fileへ散る | 変わる理由が同じ処理を近づける |
| 一fileが複数理由で変わる | 責任を分離する |
| 未要求の汎用化 | 現在必要な最小形へ戻す |
| 長い呼出し連鎖 | 相手の内部構造を公開しない |
| 中継だけの部品 | 価値のない間接化を除く |
| 実装しない継承契約 | 契約を見直しcompositionを使う |

規約違反とheuristicを区別し、toolが保証する項目を重ねて報告しない。観点別の所見、根拠位置、影響、改善案を返す。二つの観点が両方成功したかは別々に示し、一方の成功で他方の欠落を隠さない。
